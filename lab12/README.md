# Лабораторная работа №12: CRUD-приложение с MySQL и PDO, подготовленные запросы

Веб-приложение **«Каталог книг (Библиотека)»**, реализованное в рамках **Варианта №1** методических указаний. Программа написана на языке PHP и реализует полноценный цикл CRUD для управления каталогом литературы, серверную валидацию, безопасный вывод и транзакционную логику выдачи книг с журналированием.

## 📋 Спецификация Варианта №1
* **Предметная область:** Библиотека
* **Основная сущность (`books`):** `isbn` (бизнес-код), `title`, `author`, `copies` ( предметные поля)
* **Составная операция:** Выдача книги (уменьшение остатка) и одновременная запись в журнал аудита `audit_log`.

## 🛠 Среда разработки и требования
* **Язык:** PHP 8.4+
* **База данных:** MySQL 8.4+ (InnoDB)
* **Веб-сервер / Окружение:** XAMPP для Windows
* **Интерфейс БД:** phpMyAdmin
* **Архитектурный паттерн:** Трехуровневая модель (3-Tier Architecture) с разделением ответственности (SoC).

## 🛡 Реализация механизмов безопасности

1. **SQL Injection:** Полностью исключена за счет использования подготовленных запросов (`Prepared Statements`). В параметрах PDO отключен режим эмуляции (`PDO::ATTR_EMULATE_PREPARES => false`), что гарантирует выполнение запросов на уровне бинарного протокола MySQL. 
2. **Динамическая сортировка:** Имена столбцов для сортировки фильтруются в репозитории через строгий белый список (`allowlist`).
3. **XSS (Cross-Site Scripting):** Весь динамический пользовательский вывод в HTML-шаблонах экранируется функцией `htmlspecialchars($value, ENT_QUOTES, 'UTF-8')`.
4. **CSRF (Cross-Site Request Forgery):** Все изменяющие состояние базы данных операции (`STORE`, `UPDATE`, `DELETE`, `ISSUE`) принимаются исключительно методом `POST` и защищены валидацией уникального токена из сессии (`$_SESSION['csrf_token']`).
5. **Защита от утечки секретов:** Отключен подробный вывод системных ошибок (`PDOException`, стек вызовов) пользователю. При сбое конфигурации выдается нейтральное сообщение: *«Сервис временно недоступен»*.

## 🔄 Транзакционная операция (Специфика Варианта 1)
В приложении реализован метод `BookRepository::issueBookWithAudit()`, объединяющий два связанных действия в атомарную транзакцию (`beginTransaction` -> `commit` / `rollBack`):
1. Уменьшение количества доступных копий книги в таблице `books` на 1 (при условии, что `copies > 0`).
2. Добавление записи в журнал аудита `audit_log` об успешной операции выдачи книги.

При возникновении любого системного или бизнес-исключения на втором шаге транзакция откатывается полностью, гарантируя целостность данных и не позволяя списать книгу без фиксации в журнале.

## 🚀 Инструкция по развертыванию приложения

### 1. Подготовка базы данных
1. Запустите модули **Apache** и **MySQL** в панели управления XAMPP.
2. Перейдите в **phpMyAdmin** (`http://localhost/phpmyadmin/`).
3. Откройте вкладку **SQL** и выполните скрипт из файла `database/schema.sql` для создания базы данных `php_library` и таблиц `books`, `audit_log`.

### 2. Настройка подключения к БД
Если ваш MySQL в XAMPP работает на нестандартном порту (например, `3307`), убедитесь, что в файле `src/Database/ConnectionFactory.php` указан соответствующий порт:
```php
$port = '3307';
```

### 3. Запуск веб-приложения
Откройте браузер и перейдите по адресу:
```text
http://localhost/lab12/public/
```

## 📊 Матрица протестированных сценариев
Приложение успешно протестировано по следующим 12 обязательным сценариям методических указаний:
1. **Корректное создание** — запись успешно добавляется, генерируется AUTO_INCREMENT ID.
2. **Пустое поле / Неверный формат** — валидатор перехватывает ошибку до SQL-запроса, выводятся сообщения рядом с полями.
3. **Дубликат кода (ISBN)** — обрабатывается исключение `PDOException` с кодом `23000`, выводится понятный конфликт.
4. **Чтение существующего ID** — открывается детальная карточка книги.
5. **Неизвестный ID** — приложение отдает заголовок `404 Not Found`.
6. **Изменение значений** — данные обновляются, выполняется Redirect 303.
7. **Прежние значения** — при сохранении формы без изменений не генерируется ложная ошибка `rowCount == 0`.
8. **Удаление записи** — удаление происходит строго через POST-запрос с проверкой CSRF.
9. **SQL-инъекция в поиске** — кавычки и спецсимволы безопасно обрабатываются как обычный текст.
10. **Тег `<script>` в названии** — скрипт экранируется и выводится текстом, XSS-уязвимость заблокирована.
11. **Неверная сортировка** — при подмене GET-параметра сортировки срабатывает `allowlist` и применяется поле по умолчанию.
12. **Ошибка второго шага транзакции** — при симуляции сбоя на этапе записи в `audit_log` срабатывает `rollBack()`, и количество копий книги не уменьшается.
